# Phoneme models (A4-models)

Two CTC phoneme models feed `PhonemeRecognizer` (A2). A4 builds them with the Python
tools in `tools/models/` and publishes them as GitHub Release assets with a SHA-256
manifest. Model binaries are never committed: `tools/models/{release,work,data}/` are
git-ignored.

| Tier | Source model | File | Size | Status |
| --- | --- | --- | --- | --- |
| Full (optional download) | facebook/wav2vec2-lv-60-espeak-cv-ft (Apache-2.0), unchanged weights | `full-model.onnx` + `full-vocab.json` | 355.4 MB (fp32 1,263.8 MB) | built and verified |
| Light (bundled) | facebook/wav2vec2-base (Apache-2.0) fine-tuned on eSpeak RP phoneme labels | `light-model.onnx` + `light-vocab.json` | about 95 MB (measured on the base architecture) | pipeline ready and smoke-tested; GPU training run still to do |

## Model file contract (what A2 loads)

- ONNX opset 17, CPU execution provider, one `.onnx` and one `vocab.json` per tier.
- Input `input_values`: float32 `[batch, samples]`, 16 kHz mono, normalised to zero mean and unit
  variance per clip (as Wav2Vec2FeatureExtractor `do_normalize`). Batch and length axes are
  dynamic. There is no `attention_mask` input; A2 runs one clip at a time without padding.
- Output `logits`: float32 `[batch, frames, vocab]`, raw logits with one frame per 20 ms
  (about `floor((samples - 400) / 320) + 1` frames). A2 applies log-softmax.
- `vocab.json` uses the Hugging Face format `{token: id}`; column *i* of the logits is the token with
  id *i*. The CTC blank is `<pad>`, id **0**. The other special tokens are `<s>`=1, `</s>`=2 and `<unk>`=3.
- Full vocab: **392** tokens, the model's own multilingual eSpeak inventory. Its English tokens follow
  eSpeak `en-us`, e.g. `oʊ`, `ɚ`, `ɑːɹ`, `ɔːɹ`, `ɛɹ`, `ɪɹ`, `ʊɹ`, `aɪɚ`. British symbols also exist (`əʊ`, `ɒ`, `eə`, `ɪə`, `ʊə`).
- Light vocab: the specials plus every token that appears in the training labels, **in full-vocab
  order and using the same strings**. A3's IPA-to-vocab table therefore serves both tiers.
- Quantisation: ONNX Runtime dynamic quantisation with **uint8 (QUInt8) weights**. This follows A2-runtime's
  finding that ONNX Runtime's CPU ConvInteger kernel does not accept int8 weights.
  - Full tier: only MatMul/Gemm are quantised (no ConvInteger).
  - Light tier: Conv is quantised as well (`--quantise-conv`), to get under 100 MB.
- Manifest names are flat (`light-model.onnx`, `light-vocab.json`), because Flutter does not bundle
  subfolders of `assets/models/`.

## Full tier results

Measured on 2026-10-19 on an 8-CPU x86_64 WSL2 machine without a GPU, using ONNX Runtime 1.31 and torch 2.14.1.
Full report: `tools/models/work/full/report.json` (regenerated by the script).

| Measure | fp32 ONNX | int8 ONNX (uint8 weights, shipped) |
| --- | --- | --- |
| Size | 1,263,796,343 B (1.26 GB) | 355,431,615 B (355 MB) |
| Logits vs PyTorch, 20 clips: max / mean abs diff | 0.00083 / 0.0000095 | 7.88 / 0.163 |
| Max abs log-prob diff (worst frame of any clip) | 0.0013 | 11.1 |
| Frame argmax agreement with PyTorch | 100% | 99.2% |
| PER, 60 held-out clips, `en-us` references (strict / loose) | 8.37% / 8.13% | 8.61% / 8.43% |
| PER, `en-gb-x-rp` references (strict / loose) | n/a | 16.2% / 15.0% |
| CPU time for 20 s of audio, 1 thread | 17.8 s | 10.6 s |
| CPU time for 20 s of audio, 4 threads | 10.1 s | 5.6 s |

- **Held-out set**: 60 VCTK clips (15 each) from p225, p228 and p229 (female, Southern England)
  and p227 (male, Cumbria). The first 20 clips, taken round-robin across speakers, are the logits check.
- **PER**: greedy CTC decoding against eSpeak NG phonemes of the transcript; edit distance divided by the
  reference length.
  - The model was trained on `en-us` eSpeak labels, so the `en-us` reference is the fair accuracy figure.
  - The RP figure is higher because the model writes American forms (`oʊ`, r-coloured vowels) for British speech.
    A3/I2 should expect that and map them.
  - "Loose" PER ignores length marks and r-colouring inside multi-character tokens.
- **CPU times** are desktop x86 numbers, and other agents were sharing the machine. A2 measures on phones.
  A 60-word passage (about 25 s) is about 7 s on 4 desktop threads with the full model. The < 2.5 s phone target
  for the full tier looks out of reach without a smaller or streaming model; that is A2/I2's call.
- **Quantisation variants tried** (same clips):

  | Variant | Size | Argmax agreement | PER (`en-us`) |
  | --- | --- | --- | --- |
  | int8 MatMul | 355.4 MB | 99.0% | 8.37% |
  | **uint8 MatMul (chosen)** | 355.4 MB | 99.2% | 8.61% |
  | uint8 MatMul+Conv (same layout as onnx-community `model_quantized.onnx`) | 317.7 MB | 96.5% | 9.16% |

  uint8 MatMul+Conv is slower on x86.

## Light tier

**Pipeline** (`tools/models/train_light.py`):
1. Phonemise each transcript with eSpeak NG `en-gb-x-rp` (run as a binary).
2. Strip stress marks and map to full-vocab tokens.
3. Build the light vocab (blank `<pad>` = 0).
4. Fine-tune `facebook/wav2vec2-base` (pinned revision) with CTC:
   - the conv feature encoder is frozen;
   - AdamW with linear warm-up and decay;
   - SpecAugment time masking 0.05 and layerdrop 0.05;
   - length-bucketed batches;
   - validation PER on held-out speakers.
5. Export with `--quantise-conv` and evaluate on the same held-out set with RP references.

**Proven on CPU** with `tools/models/reproduce.sh light-smoke`:
- a tiny random wav2vec2 trained for 30 steps on 40 real VCTK clips from p250, with real eSpeak labels;
- export, uint8 quantisation (logits within 0.6 of fp32, 99.9% argmax agreement) and evaluation all ran end to end;
- PER is 100%, as expected for a 30-step tiny model.

The real `wav2vec2-base` path was also checked on CPU: the model loads with a new 49-token head, and training steps
run (about 15 s per step at batch 8 × 3 s on 8 CPUs, which is why the real run needs a GPU). Exported, it is
377.9 MB fp32, **95.2 MB** with uint8 MatMul+Conv, and 122.0 MB with uint8 MatMul only.

**Real training run** (not done here; needs a CUDA GPU):

```bash
# on a GPU machine with eSpeak NG installed (apt install espeak-ng), from the repo root
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements-dev.txt
.venv/bin/pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cu126  # CUDA build
.venv/bin/pip install -r tools/models/requirements.txt --no-deps
tools/models/reproduce.sh full      # once: needed for full-vocab.json (and the full tier)
STEPS=20000 tools/models/reproduce.sh light
tools/models/reproduce.sh release   # manifest + SHA256SUMS for both tiers (dry run)
```

- **Training data**: the VCTK speakers with accent "English" (33), minus the 5 held-out speakers. That is
  about 28 × 400 clips, roughly 11,000 utterances or about 9 h of read speech.
- **Recipe**: 20,000 steps at batch 16, lr 1e-4, fp16.
- **Expected cost (estimate)**: about 1.5–3 h on one 24 GB GPU (A10G, L4 or RTX 4090), or about 1 h on an A100.
  At typical cloud prices that is roughly US$2–6, plus about 10 GB of downloads. On CPU the same run would take
  weeks.
- If PER is poor, add LibriSpeech train-clean-100 (CC-BY-4.0, about 100 h, mostly American) to the training
  data. Keep RP labels and VCTK for validation.

## Reproducing everything

`tools/models/reproduce.sh {full|light-smoke|light|release}`. It needs Python 3.12, about 6 GB of RAM for the
full export, and eSpeak NG on PATH (or `ESPEAK_NG=/path/to/espeak-ng`). Individual steps:

```bash
python -m tools.models.export_onnx --model facebook/wav2vec2-lv-60-espeak-cv-ft \
    --out tools/models/release/full --work tools/models/work/full
python -m tools.models.data --speakers p225,p227,p228,p229,p232 --per-speaker 12 \
    --out tools/models/data/eval                       # downloads only the shards needed
python -m tools.models.evaluate --model facebook/wav2vec2-lv-60-espeak-cv-ft \
    --release tools/models/release/full --work tools/models/work/full \
    --verify-clips tools/models/data/eval/manifest.tsv \
    --eval-clips tools/models/data/eval/manifest.tsv --ref-voice en-us
python -m tools.models.release --release-dir tools/models/release   # dry run
```

The reported run used `--parquet` with shards 10 and 22 downloaded beforehand, `--per-speaker 15`, and four
of the five held-out speakers. The fifth, p232, is in shard 33 and was skipped to save bandwidth.

## Publishing (GitHub Release assets)

`python -m tools.models.release --release-dir tools/models/release --repo OWNER/REPO --tag models-v1 --publish`

1. Writes `manifest.json` and `SHA256SUMS` and re-verifies them.
2. Creates release `models-v1` with `gh`, uploading `full-model.onnx`, `full-vocab.json`, `light-model.onnx`,
   `light-vocab.json`, `manifest.json` and `SHA256SUMS`.

Without `--publish` it is a dry run. **Nothing has been published yet.**

**Download URL placeholder:**
`https://github.com/OWNER/REPO/releases/download/models-v1/<asset>`
Replace `OWNER/REPO` once the repository is public or has a release token.

After publishing, A2 copies `tools/models/release/manifest.json` to `assets/models/manifest.json`. CI
(`tools/ci/fetch_models.py`, `integration.yml`) then downloads each file, checks its SHA-256 and caches it.
Light files are marked `bundle: true` (copied into `assets/models/`); full files are only cached.
